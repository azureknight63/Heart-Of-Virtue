Three options per round, unchanged. What changes is the label: the button now shows kind (what Jean talks about) instead of tone, and tone widens to the eight portrait emotions.

What drives each row. The text and both labels come from one LLM call per round. kind is rendered in the label slot the tone used to occupy — right-aligned, 11px, colors.text.dim — so the diff in NpcChatPanel.jsx:622 is one field name, not a layout change. Rows keep padding: spacing.md and a 44px minimum height.
Rule 2 of the design note is visible here: the third row is a reply. At least one always is — three questions in a row leave Mara's last line unanswered and read as interrogation. If the model returns none, QC replaces the last row from the fallback pool, which is all replies.
Jean's portrait carries the emotion of the option he last chose, so it lags the options on screen by one turn. That is unchanged behaviour; only the vocabulary widens.

3 · Tone collisions are fine now — and the reply rule

Two options, one emotion

portrait per row → skeptical· skeptical· neutral

Degraded round — LLM unusable

portrait per row → neutral· skeptical· curious

Left: rows 1 and 2 share the skeptical portrait and still read as plainly different choices, because the kind disambiguates them. That is what makes it safe to delete the tone re-keying in _qc_jean_options — the duplicate-tone bug it guards against was a legibility bug, and the kind label is what now carries legibility. It is only safe while the kind is shown. Hide the label and the old bug returns.
Right: _JEAN_FALLBACK_POOL is tagged reply throughout, so a round the model could not serve degrades to three replies — visibly duller, never broken, and rule 2 ("at least one reply") is satisfied for free. Its three tones are the migration of the TONE_EMOTIONS table being deleted: direct→neutral, guarded→skeptical, open→curious.

4 · Jean's portrait emotion — the tone axis, widened

tone ≡ emotion. Today three registers map onto three of these eight via TONE_EMOTIONS; five portraits Jean already has art for are unreachable from chat. Widening JEAN_TONES to the full EMOTIONS vocabulary (utils/portraits.js:30) deletes the mapping table rather than growing it — toneEmotion() becomes the existing normalizeEmotion(). skeptical is highlighted as the emotion the hovered option above would select.

5 · Kind vocabulary — label treatments

Plain (spec)Tinted (alt)Gloss sent to the model

redirectredirectreturns to a subject the NPC raised earlier

close was considered and rejected — the player ends a conversation by dismissing the dialog. confide is deferred, not refused.

Two treatments, one decision left. The design note specifies the plain column: one dim label, identical in weight to today's tone label, no new colour. The tinted column is offered because six kinds are more scannable with a hue, and it stays inside the accessibility rule (colour is paired with the word, never carrying state alone) — but it puts six more colours into an amber-themed dialog. Plain is the recommendation; tinted is here so the choice is visible rather than assumed.
The pool is an ordered mapping in ai/llm_client.py that the prompt renders from, so adding or renaming a kind is a one-line edit — this table is a snapshot of a constant, not a fixed set.

Why the tone label is dropped rather than joined. At 390px the option text already wraps to two or three lines; a two-part [skeptical · ask-lore] label either wraps with it or squeezes the text column. One label holds. The emotion is on the portrait, which is the only place it was ever needed.
Rows stay ≥44px, the label never falls below 11px, and nothing here is conveyed by colour alone.
