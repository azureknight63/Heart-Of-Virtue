## Findings

### Finding 1 — LLM connection down for all three NPC chats (llm_available: false)

- **Severity**: High (blocks the core LLM-voice verification this run was staffed to do; also a live-service concern)
- **Location**: NPC chat panel, any NPC, `camp` stack
- **Steps to reproduce**: Open `talk` on Mara, Devet, or Liss; pick any Jean dialogue option.
- **Expected**: A live model-generated reply, per `NPC_CHAT_LLM_ENABLED=1` on this stack.
- **Actual**: Every single opening line and every follow-up carried the banner "Connection unavailable — this reply is scripted, not generated." (`LlmDegradedNotice`, `frontend/src/components/NpcChatPanel.jsx:304-318`, driven by `llm_available` in the `/api/npc/chat/open` and `/respond` payloads — `src/npc/_chat_llm.py:4206`). Every line I received matched a canned `conversation_starters_by_chapter["1"]` or `closing_lines_when_exhausted` entry verbatim from the NPC's own JSON file (see Dialogue voice notes). Conversations auto-ended after exactly 2 exchanges every time, for all three NPCs, using the exhaustion closing line.
- **Confidence**: Reproduced 3/3 NPCs (Mara, Devet, Liss), 2 exchanges each, 100% degraded.
- **Note**: This is very likely a live-outside-my-control infra issue (dead/misconfigured OpenRouter/Groq/Cerebras model per `.claude/rules/llm-prompts.md`'s "vendors retire model slugs" gotcha), not a code defect I can fix or root-cause further from here — I have no server log access from the browser driver. Whoever triages this should check `logger.info("chat_open start npc=%s llm_available=%s..."`) in the backend log and the provider's model-catalogue status.
- **Positive side note**: the game degrades gracefully and *transparently* — the banner is honest about the fallback, so a player is never fooled into thinking a canned line is a live one. This is good design and should not be "fixed" by hiding the banner.

### Finding 2 — Mojibake (double-encoded UTF-8) in several Nomad Camp tile descriptions

- **Severity**: Low (cosmetic, but visible on every visit to affected tiles)
- **Location**: `eastern-descent-nomad-camp` map — confirmed on Rivers Edge (1,2), Camp Far Edge (3,4), Water Step (0,2)
- **Steps to reproduce**: Visit any of the above tiles; read the tile description.
- **Expected**: A real em dash (—).
- **Actual**: Literal `â€"` (or similar three/four-byte mojibake) appears where an em dash should be, e.g. Water Step: *"The river is close here â€" cold water and silt smell..."* Confirmed at the source: `src/resources/maps/eastern-descent-nomad-camp.json:1556` stores the raw bytes `â€”` in the CampFarEdge description — this is UTF-8 bytes for an em-dash that got re-decoded as Latin-1/cp1252 before being saved as JSON.
- **Evidence**: screenshot `T3_008_riversedge_mojibake.png`; text dumps in this session at Rivers Edge, Camp Far Edge, Water Step.
- **Confidence**: Reproduced on 3 separate tiles, all in the same map file — not a one-off. Dynamically-generated narration (e.g., the Ferry Landing's `end_demo()` line, "...The way is plain enough — but not today.") renders the em dash correctly, which confirms the corruption is isolated to this one map JSON's authored description strings, not a systemic encoding bug in the narration pipeline.

### Finding 3 — DevetIntroEvent and LissObservingEvent fire one move late

- **Severity**: Medium
- **Location**: Fire Ring (3,2) and Camp Far Edge (3,4), `eastern-descent-nomad-camp`
- **Steps to reproduce**: Move directly onto Fire Ring (3,2) or Camp Far Edge (3,4) for the first time.
- **Expected**: The intro scene fires immediately on entry, like every other scripted event tested this run (GorranGesture, NomadCampSmell, CampEntryGreeting, MaraFirstContact, IronAndOathIntro, MaraObservation all fired on the very move that entered the tile).
- **Actual**: `pending_events: 0` on first entry to both tiles — no scene. Moving one more step off the tile and immediately back on triggers the scene correctly (full text, correct gate-setting afterward).
- **Confidence**: Reproduced on both affected tiles (2/2), each only tested once (didn't want to burn budget re-confirming). Both tiles' event props in the map JSON share `"delay_duration": 3000, "delay_mode": "combat"` (see `eastern-descent-nomad-camp.json` lines ~19-36 for FireRing) — my best guess, not confirmed, is that this delay/mode combination needs one extra `game_tick_events()` call before the condition check passes, which only happens on the *next* move. IronAndOathIntroEvent, which fired instantly, may not share these props — worth a diff of the four events' JSON blocks.

### Finding 4 — Combat nav-bar buttons intercepted by stale panel overlay

- **Severity**: Low (real accessibility/hit-testing defect, but a raw click always got through)
- **Location**: Combat UI, category nav bar (`OFFENSIVE`/`MANEUVER`/`MISC`/`DEFENSIVE`)
- **Steps to reproduce**: In combat, switch categories rapidly (e.g., click `MISC` right after `OFFENSIVE`'s panel rendered).
- **Actual**: Playwright's real click was refused with `<div class="game-panel...">…</div> subtree intercepts pointer events` / `<p class="game-text ">Offensive MOVES</p> from ... intercepts pointer events`. A raw synthetic click (`raw_click`) always got through and the correct panel opened.
- **Confidence**: Reproduced twice during the Hounds Warren and Scree Shelf fights. Not a soft-lock (raw click always worked) but a genuine hit-test/a11y defect — the outgoing panel's text node is still capturing the click target when the new one should be receiving it.

## Non-bug observations

- The scripted scenes throughout the Nomad Camp are long (5+ beats each) and consistently well-attributed; portrait swaps for entering/exiting characters (Liss's fade-in/out in CampEntryGreeting and Iron & Oath) read cleanly.
- Combat cooldown/fatigue pacing against fodder enemies (Rock Rumblers, Talus Hounds) required several `Wait`/`Rest`/`Dodge` filler actions between `Attack` cooldowns at level 4-5 — not a bug, just slower than I expected given the "one-shot kill" damage numbers; a real player will spend real wall-clock time here even though each individual fight is not dangerous.
- A natural level-up (4→5) fired mid-route after the Hounds Warren fight, with the mandatory attribute-allocation gate blocking loot collection until points were spent (used `RANDOMIZE`) — this is documented as intentional in the primer and behaved exactly as described.
- Story Log (Journal → STORY LOG tab) is a good verification tool — it kept a clean, tile-by-tile transcript of every scene, and was reliable evidence for cross-checking branch text (e.g. the has-mace branch of MaraObservationEvent) after the modal itself had been dismissed.
