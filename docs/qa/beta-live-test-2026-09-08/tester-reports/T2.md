## 5. Findings

### Finding 1 — Multiple object keywords throw visible backend errors instead of working
- **Severity: High** (UI action not working, reproduced on 3+ distinct object instances across 2 object classes)
- **Location**: (10,6) Fabricarium — Floor Channel Grate; (11,3)/conclave-archive Reading Hall — Stone Tablets; (8,4) Arcology — Carved Lintel
- **Steps to reproduce**:
  1. Navigate to (10,6) in Grondia, open INTERACT, Search Area, click Floor Channel Grate, click "lift"
  2. Navigate to grondia-conclave-archive (2,2), click Stone Tablets, click "touch", "check", "view", or "inspect" in turn
  3. Navigate to (8,4) in Grondia, click Carved Lintel, click "touch"
- **Expected**: keyword produces a flavor response (as "read"/"examine"/"open"/"search"/"look" do on the same objects)
- **Actual**: dialog shows `⚠️ Error executing action: 'Container' object has no attribute 'lift'` (Floor Channel Grate) and `⚠️ Error executing action: 'WallInscription' object has no attribute 'touch'` / `'check'` / `'view'` / `'inspect'` (Stone Tablets, Carved Lintel). The button remains clickable and re-throws every time.
- **Evidence**: screenshots `T2_001_t2_bug_grate_lift.png`, `T2_003_t2_bug_lintel_touch.png`. No console/network error was raised for these (backend swallows the exception and returns a user-facing error string), so `allerrors` does not surface them — must be caught via UI text.
- **Confidence**: reproduced on 3 separate object instances (2 Container/`lift`, and touch/check/view/inspect on 2 separate WallInscription instances). On WallInscription only "read" and "examine" are safe; on this Container instance "search", "look", "open" worked but "lift" did not.
- **Suggested root cause**: the `Container` and `WallInscription` classes expose a keyword list to the frontend (for the sub-dialog buttons) that is broader than the set of methods actually implemented on those classes — the button list and the method dispatch table have drifted apart.

## 6. Non-bug observations
- The (7,5) Arcology tile fires an unskippable scripted cutscene (Gorran leading Jean to a Citadel elder) that **teleports the player from (7,5) directly to (10,5)**, skipping the geographic path in between. This is presumably intentional story staging, but it means players who explore linearly will "miss" walking through (8,4)-(9,4)-(9,3)-(10,2)-(10,3)-(10,4) on their first pass and have to backtrack — worth a design gut-check if backtracking wasn't intended.
- NPCs are uniformly rendered with the same 👤 icon in the INTERACT list whether they're the permanent ally (Gorran) or ambient Grondites — consistent, but I could not test the hostile-vs-ally distinction from #537 since Grondia has no hostile NPCs in this build.
- The "Take All Items" quick-action button (seen on some tiles, e.g. vacated-dwelling 2,2) is a nice UX shortcut that bypasses the container-search flow entirely when items sit loose on a tile — inconsistent with tiles that require Search Area first, but that inconsistency tracks the map's "Container" vs plain "items" tile-type design, not a bug.
- Talk interactions with named/ambient NPCs (Grondite Elders, Grondite Workers, Mynx) consistently produced a rendered scripted reply with no LLM prose and no crash — LLM-off gating confirmed working correctly throughout.
