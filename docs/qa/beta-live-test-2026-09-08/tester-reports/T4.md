This run is the mobile-playability pillar check: measure, don't re-find T3's story bugs. ## C. Layout integrity at 375px

- **Horizontal scroll**: never observed. Checked `scrollWidth`/`clientWidth` at exploration, combat (category panel open), battlefield map (4-portrait VN, 2×2 grid), Feedback dialog, and Victory dialog — always 375==375.
- **Panel overlap/clipping**: none found. The 2×2 portrait grid holds cleanly through 4 simultaneous speakers.
- **Room description**: readable, full-width, not truncated (scrolls internally with a `▼ scroll ▼` affordance — correct pattern, not a bug).
- **Mini-map**: fits. The MAP tab embeds an 8-direction d-pad *above* the grid map, itself scrollable/pannable; no overflow.
- **Combat battlefield**: fits at 375px. HP badges render as colored pills but always carry visible numeric text ("200/200", "48/48") — see section D. One UX nudge worth noting: a status banner "⚠ Enemy off-screen — switch to Fit Fight" appeared when an enemy was far from Jean on the battlefield canvas; text-labeled, not a bug, but confirms the battlefield canvas itself can run out of visible room at this viewport for spread-out fights.
- **Header disappears off the MAP tab**: the `⚙️`/`Feedback`/`Account` header row is present in the DOM only while the CHARACTER tab is active — it is absent entirely (not just occluded) while viewing the MAP tab. Confirmed via `aria()` diff: same page, MAP tab shows only the World Map complementary region + the two bottom tabs, no header controls at all. Not severity-Critical (one tap on CHARACTER restores it) but it means a player who opens Settings or Feedback mid-navigation has to leave the map first. Low/Medium finding — see Findings.

## D. Colour-only state

- **Exploration home panel HP/Fatigue bars: colour-only for sighted players.** The two vertical bars flanking the heart icon (red = HP, orange = Fatigue) carry **no visible numeric text on screen** — confirmed by screenshot (`T4_025_24_hpbar_coloronly.png`, also visible in the very first screenshot `T4_001_00_start.png`). The only text equivalent is in the accessibility tree (`progressbar "HP: 91 / 116"`), which helps screen-reader users but does nothing for a sighted low-vision or colorblind player watching two colored bars shrink with no label. This is the same class of issue as #536 (which flagged combat HP capsules) but in a **different, still-unfixed** location — the exploration/character-panel view. Recommend: either overlay "91/116" text on the bars, or surface it without requiring a tap into ATTRIBUTES.
- **PARTY panel**: correctly labeled — "HP 118 / 214" as visible text above a bar. **PASS.**
- **Combat target-select dialog**: correctly labeled — "HP: 200/200" visible text next to the bar for every target. **PASS.**
- **Battlefield map HP badges**: correctly labeled — "200/200", "48/48" rendered as visible numeric text inside the colored pill. **PASS.**
- **INTERACT dialog NPC/object tags**: "NPC" and "OBJECT" are colored-outline badges but carry the word itself as text, not color alone. **PASS.**
- **Disabled move reasons** ("⚠ Cannot use this move", "⚠ Available in 5", "⚠ No valid target in range") always pair an icon + text, never color alone. **PASS.**
- **Combat category panel color coding** (red OFFENSIVE / gold MANEUVER / green INVENTORY / gray MISC / orange DEFENSIVE): each button carries its own text label, so this is decoration, not information. **PASS.**

Net: one real regression-adjacent colour-only finding (home HP/Fatigue bars), everything else checked was properly labeled.

## Findings

### Finding 1 — Battlefield toolbar buttons fail the 44px touch target (Low-Medium)
- **Severity**: Low (not a blocker — the buttons are far apart and mis-taps are unlikely — but a clear, systematic miss)
- **Location**: Battlefield Map view, combat, any encounter (e.g. eastern-descent (1,2) High Ledge)
- **Steps**: Enter combat → tap 🗺️ BATTLEFIELD tab → observe the "Overview" / "Enemies (N)" / "Follow" / "Fit Fight" button row
- **Expected**: ≥44×44 CSS px per the accessibility pillar
- **Actual**: Overview 75.6×28, Enemies (1) 97.2×28, Follow 63.2×26, Fit Fight 84.8×26 — measured via `bounding_box()`
- **Evidence**: `T4_009_08_battlefield_tab.png`; raw measurement JSON in session log
- **Confidence**: reproduced across two different combat encounters (both Rock Rumbler fights, plus the Talus Hound fight)

### Finding 2 — Feedback dialog severity selector (LOW/MEDIUM/HIGH) is 28px tall (Low)
- **Severity**: Low
- **Location**: Feedback dialog, any tile (opened at Grondia and again at Tradepost)
- **Steps**: Tap Feedback (header, CHARACTER tab) → scroll to Severity row
- **Expected**: ≥44px height
- **Actual**: 96.8×28 for each of LOW/MEDIUM/HIGH
- **Evidence**: `T4_023_22_feedback_dialog.png`
- **Confidence**: reproduced twice (opened dialog twice this session)

### Finding 3 — Exploration home panel HP/Fatigue bars are colour-only, no visible number (Medium)
- **Severity**: Medium (same defect class as closed #536, in a location the original fix didn't cover — a colorblind or low-vision player has no way to read exact HP/Fatigue from the main screen)
- **Location**: CHARACTER tab home view, every tile (first seen Grondia Antechamber (14,5), still present at Tradepost (4,3) after ~2 hours of play)
- **Steps**: Open the game on CHARACTER tab (default view) → observe the red bar (left of heart) and orange bar (right of heart)
- **Expected**: a visible number pairs the colour, per CLAUDE.md's "state is never color-only" accessibility pillar
- **Actual**: only accessible-tree text (`progressbar "HP: 91 / 116"`) exists; nothing renders on screen. Confirmed by full-page screenshot, not just DOM inspection.
- **Evidence**: `T4_025_24_hpbar_coloronly.png`, also visible in `T4_001_00_start.png`
- **Confidence**: reproduced across the entire session (every exploration screenshot shows the same pattern) — not a one-off render glitch

### Finding 4 — Header controls (Settings/Feedback/Account) vanish entirely on the MAP tab (Low)
- **Severity**: Low
- **Location**: Any tile, MAP tab
- **Steps**: Tap 🗺️ MAP tab → run `aria()` / inspect the header row
- **Expected**: header persists (or is reachable) regardless of which bottom tab is active
- **Actual**: the header (`⚙️`, `Feedback`, `Account`) is absent from the DOM entirely while MAP tab is active — not clipped, not scrolled off, genuinely not rendered. Confirmed by comparing `aria()` output on CHARACTER vs MAP tab at the same tile.
- **Evidence**: aria() diffs in session transcript (CHARACTER tab shows 3 header buttons; MAP tab shows none)
- **Confidence**: reproduced twice (checked at two different tiles)

### Finding 5 (non-mobile, informational) — Rock Rumbler enemies appear to fully resist the starting Shortsword
- **Severity**: not scored (out of scope — combat balance, not layout/touch)
- Both Rock Rumbler fights logged repeated "Jean struck [enemy] but did no damage!" with the combat API's own damage preview showing `{"min": 0, "max": 0}` for Attack against Rock Rumbler while other party members' hits and eventual Jean hits (after several rounds) did connect. This consumed the bulk of this session's combat time (both fights only closed once Gorran's damage output, and eventually a few connecting Jean strikes, wore the enemies down). Flagging for the balance/combat owner, not filing as a mobile bug — plausibly an intentional "resist slashing, needs a different weapon class" puzzle (Rock Rumblers are earth/stone creatures), but the in-fiction hint for that (if any) wasn't obvious from move descriptions alone.

### Finding 6 (Low, cosmetic) — React `validateDOMNesting` warning in Victory dialog
- **Severity**: Low, cosmetic/console-only
- One console error during the first Victory dialog: `Warning: validateDOMNesting(...): <p> cannot appear as a descendant of <p>`, traced to `GameText.jsx` inside `VictoryDialog.jsx`. Did not visibly break layout at 375px (checked the screenshot — text rendered fine), but it's a real markup bug worth a quick fix.
- **Evidence**: console log seq for that call, see full error dump

## Non-bug observations

- The mobile UI is a genuinely different, purpose-built layout, not a squeezed desktop layout — bottom tab bar (CHARACTER/MAP), an embedded d-pad inside the MAP view, a 2×2 responsive portrait grid for VN scenes. This is a real redesign since the #541/#542 audit, not a patch.
- Combat pacing on a phone (as tested via Playwright, real-time) required active engagement every ~10–20 real seconds (submitting Rest/Wait/Attack each beat window) — not a bug, but worth knowing if a future mobile session runs into a similar-feeling "nothing is happening" moment: the beat clock does not progress on its own; a move must be submitted.
- The "🔍 Search Area" INTERACT row (37.5px tall) and the Feedback title input (42px) are both just barely under 44px — worth a one-line CSS pass alongside the two clearer failures in Findings 1–2, since they're close enough that a small padding bump would clear all four issues in this report at once (Overview/Enemies/Follow/Fit Fight excepted, which need real work).
