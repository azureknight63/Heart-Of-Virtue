## 4. Findings

### Finding 1 — `Container` "TAKE ALL" is broken everywhere it was tried (High)
- **Severity:** High (a core, constantly-used loot action silently fails with a diegetic-looking error and leaves contents in place)
- **Location:** Grondia (3,5) Wall Niche; Grondia (9,5) Work Platform; also implied by #600 at Jambo's tent crate (camp stack, not tested by me)
- **Steps to reproduce:**
  1. From session start, go S, SE to (3,5).
  2. INTERACT → Search Area → Wall Niche → `open`.
  3. Click `TAKE ALL`.
- **Expected:** All container contents transfer to inventory in one action.
- **Actual:** `⚠️ There's no way for Jean to take_all the Wall Niche.` — nothing is taken, button stays present. Single `TAKE` on each row works fine immediately after. Reproduced identically at (9,5) Work Platform (already-open container, no `open` step needed) — same error text, same failure mode.
- **Evidence:** Screenshot `logs/qa/runs-0917/shots/T2_001_t2_wallniche_takeall_fail.png`; dialog text quoted above; no console/network error was emitted (the failure is a narrated in-fiction rejection, not a crash), so this is a backend command-dispatch bug (a `take_all` verb the `Container` object doesn't actually implement) rather than a frontend issue.
- **Confidence:** Reproduced twice on two different container instances/states (one `closed`→`open`, one pre-`opened`).
- **Suspected cause:** `Container`'s parsed-keyword handling doesn't wire up a `take_all` action the button is coded to send (contrast: the tile-level "📦 Take All Items" bulk button, used for loose floor items in `grondia-vacated-dwelling` (2,2), worked correctly and printed "Jean takes: X, Y" — so the two "take all" code paths are different, and only the `Container`-scoped one is broken).

### Finding 2 — Unpurchased Jambo's-tent merchandise is silently confiscated with zero feedback, and the tent's own "book" has no legitimate ownership path (High)
- **Severity:** High (contradicts the changelog's stated #597 fix; also a genuine content dead-end — a "personal" narrative item can never be read)
- **Location:** `grondia-jambos_shop` (2,2) Tent Entrance
- **Steps to reproduce:**
  1. Enter Jambo's Tent from Grondia (12,4).
  2. INTERACT → `Dissenting Record — The First Dormancy` (a Book lying loose among the merchant's floor stock) → `take`. It transfers into your bag.
  3. Open INVENTORY → Misc. → select the book: it shows `⚠️ MERCHANDISE - NOT OWNED`.
  4. Click `📖 Read`: `POST /api/inventory/use` → 400 `{"error":"You must purchase Dissenting Record — The First Dormancy before using it"}` (this part is a *correct* guard).
  5. Close inventory, INTERACT → Tent Flap → `enter` → `Step through` to leave, still holding the book.
- **Expected (per #597):** Some feedback — narration, toast, or a blocking dialog — when leaving with unpurchased merchandise.
- **Actual:** No dialog, toast, or narration appears during the whole transition (checked `text()`, `aria()`, and `all_errors()` — nothing). On arrival at (12,4), the book is simply gone: Misc. count dropped 7→6, weight dropped 21.8→20.9 lb, no message anywhere. Separately, the book was never listed in Jambo's `Buy` panel at all (`Restorative/Draught/Antidote/Slime Flask/Mineral Solvent/Leather Gloves` only) — so there is no way to legitimately purchase and therefore ever read this item; `read`/`examine` on it also fail directly with the generic `⚠️ There's no way for Jean to read/examine the Dissenting Record…` while unowned.
- **Evidence:** Network log: `POST /api/inventory/use → 400 "You must purchase Dissenting Record — The First Dormancy before using it"`; screenshot `logs/qa/runs-0917/shots/T2_002_t2_jambo_book_merchandise_stuck.png`.
- **Confidence:** Reproduced once, full round trip (take → inspect → attempt read → leave → inventory diff). Did not repeat a second time due to budget.
- **Suspected cause:** The confiscation-on-exit logic (implied by #597's existence) either isn't wired to emit a narration/toast on this stack, or silently deletes the item via a path that bypasses the messaging that landed with #597. Separately, `Dissenting Record — The First Dormancy`'s price/availability appears mis-configured for Jambo's `Buy` listing (visible in `sell`/inventory as `Buy: 0💰` but absent from the actual buy panel), which is likely why it can never be legitimately owned.

### Finding 3 — Enter/Space does not always dismiss a terminal story-dialog stage (Low–Medium)
- **Severity:** Low-Medium (a UX gap in #584's fix, not a soft-lock — a click always works)
- **Location:** Scene 1 tail narration, arriving at Citadel (10,5)
- **Steps to reproduce:**
  1. Play through Scene 1 (7,5)→Citadel to its final stage, where the modal shows `📜 LOG (9)` and just "Every surface has been worked to a standard." with a `CLOSE` button (not `Continue`/`Begin`).
  2. Press `Enter`, wait 1.5s.
- **Expected:** Dialog dismisses (per #584, Enter/Space should advance/dismiss story dialogs).
- **Actual:** Dialog stayed open; `page.locator(".modal-content")` still had 1 element. Clicking `CLOSE` directly worked immediately.
- **Evidence:** Sequential `aria()` dumps in this run showing the same unchanged dialog content across an Enter press + 1.5s wait, then a successful click.
- **Confidence:** Seen once, not deliberately reproduced a second time (budget).
- **Suspected cause:** The keydown handler for Enter/Space in the story-dialog component likely targets a `Continue`/`Begin` button by role/name and doesn't also bind to a `CLOSE`-labeled terminal button — a labeling/selector gap rather than a missing handler.

Both text objects cross-reference each other and a third object (`Casting Mold Rack`/`Sample Pedestal`/Batch 117-K quality report) consistently, forming a genuinely satisfying lore thread about a voided casting batch. Recommend a narrative-review pass to confirm this thread pays off later, but nothing here reads broken.
- **(10,10) GateSouth** is a fair, intentionally-hinted dead end (only `north` exit; `Gate Inscription` text explicitly signals "depth," "below," urgency) — matches the CLAUDE.md "dead end with an interactable is a puzzle, not a bug" guidance, not filed as a bug.
- The Feedback dialog correctly degrades: submitting returned a graceful `503 Feedback service is not configured on this server` (expected — the GitHub token is blanked for QA runs per ground rules) with the form data preserved and a clear retry affordance; not a bug.
- `COMMANDS` panel shows a `[DEBUG MODE ACTIVE]` label — expected under the `TESTING` config used to grant test sessions their API bypass (`routes/debug.py` gate per CLAUDE.md), but worth a sanity check that this label can never render in a genuinely non-`TESTING` build.
- Several mundane environmental texts (Notice Boards, wall inscriptions) reference the same "pool. closed. elder." throughline across at least 3 different tiles/side-maps (Grondia market Notice Board, Guesthold Notice Board, Fabricarium Allocation Board) — consistent, deliberate worldbuilding, not a bug.
- Starting gold matched the documented 315 (confirmed via early `where()`/shop panel deltas before any purchases).
