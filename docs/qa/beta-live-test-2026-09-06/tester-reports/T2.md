## Findings

### Finding 1 — Arrival-narration modal can become permanently stuck, blocking all UI (soft-lock)
- **Severity**: High (soft-lock; recoverable only via full page reload, which a player might not think to try, and which is a workaround rather than a fix)
- **Location**: Reproduced at `grondia-fabricarium-forge` (2,2), `grondelith-mineral-pools` (2,0), and `grondia-vacated-dwelling` (2,2) — all reached via a `Passageway` teleport. Not reproduced on every teleport (e.g. `grondia-jambos_shop`, `grondia-guesthold`, `grondia-conclave-archive` all opened and closed cleanly the first time).
- **Steps to reproduce**:
  1. From Grondia, walk to a tile with a Passageway object (e.g. (10,6) Fabricarium → Forge Entrance)
  2. INTERACT → object → "enter" → confirm "[1] Step through" if prompted
  3. On arrival, an "✨ Event Result" dialog shows the room's arrival narration with a "✕" (and sometimes a "Close" button + "or click anywhere to continue...")
  4. Click "✕" (or "Close", or click the dialog body, or press Escape/Enter)
- **Expected**: Dialog dismisses, tile becomes interactive
- **Actual**: Dialog reappears with byte-for-byte identical text after being dismissed; confirmed via `text()` diff before/after a click — identical. Tested via role-based click, exact-pixel-coordinate click (`page.mouse.click(1004, 288)` on the visible ✕), Escape key, and Enter key — none worked. The underlying `modal-overlay` div blocks all other buttons (Move, INTERACT, INVENTORY, etc.) for as long as this persists.
- **Evidence**:
  - Screenshot: `T2_008_t2_bug_stuck_modal_fabricarium.png` (shows the stuck dialog with a clearly-rendered, apparently-clickable ✕)
  - `where()` and `pending()` both report a clean state (`pending_events: 0`) throughout — this is a frontend-only bug, the backend session is never affected
  - A full `page.reload()` reliably recovers the exact same position/state every time (tested 4 times this session)
- **Confidence**: Reproduced 3 times across 2 different sub-maps in one session (seen twice at the Forge alone, once at Mineral Pools, once at the vacated dwelling on a later re-entry). Did not reproduce on the majority of teleports, so it is intermittent — possibly correlated with the length of the room description (all 3 reproductions were on tiles with longer, multi-sentence descriptions) or with the automation's click cadence being faster than a human's. Recommend a human tester click through several long-description room transitions at normal speed to confirm it isn't purely an automation artifact; if confirmed, this is release-blocking since a real player has no in-game way out short of guessing to refresh the browser.

### Finding 2 — React invalid DOM nesting warning in item/interact panels
- **Severity**: Low
- **Location**: `InteractPanel.jsx` / `GameText.jsx`, surfaces whenever an item or object description is shown in a panel that already sits inside a `<p>` from `GamePanel.jsx`
- **Steps to reproduce**: Open INVENTORY → click any item to see its detail card (first seen when viewing the Restorative Potion at session start)
- **Expected**: No console errors
- **Actual**: `Warning: validateDOMNesting(...): <p> cannot appear as a descendant of <p>` — full stack trace points to `GameText` nested inside another `GameText` inside `GamePanel` inside `BaseDialog` inside `InteractPanel`
- **Evidence**: console.error captured verbatim, seq 5, timestamp 19:51:44
- **Confidence**: Seen once, but the code path (item-detail rendering) was exercised many times afterward without a repeat log line (likely because the warning is deduped per React instance) — purely cosmetic, no functional impact observed.

### Finding 3 — `page.keyboard.press("1")` does not select numbered event choices
- **Severity**: Low (possible environment/automation-specific issue, not necessarily a player-facing bug)
- **Location**: Story event dialogs (`✨ Event`), e.g. the BetaTesterBriefing at (1,2)
- **Steps to reproduce**: Open the BetaTesterBriefing event, call `page.keyboard.press("1")` repeatedly
- **Expected** (per primer): keyboard "1" advances the choice, same as clicking `[1] CONTINUE`
- **Actual**: 12 consecutive `press("1")` calls left the dialog completely unchanged (verified via identical `text()` output each time); a mouse click on the same button worked immediately afterward
- **Confidence**: Seen once, not re-tested after switching to click-based advancement (to conserve budget) — flagging as "possibly intentional/automation-specific" since the primer explicitly claims this should work; a human tester should verify keyboard shortcuts still work when the game window has real focus.

### Finding 4 — Level-Up dialog with 65 unspent attribute points blocks all UI at session start
- **Severity**: Low / possibly intentional
- **Location**: (1,2), immediately after the BetaTesterBriefing event completed
- **Steps to reproduce**: Complete the BetaTesterBriefing event, then try to open any other panel (INTERACT, INVENTORY, etc.)
- **Expected**: unclear — this may be intentional (level-10 starting character needs its levelup points allocated before play)
- **Actual**: A "⭐ LEVEL UP" modal with 65 available points appears and blocks (`modal-overlay`) all other panel buttons until "Must spend all points to continue" is satisfied. Resolved via the "RANDOMIZE" button, which allocated all 65 points in one click and closed the dialog cleanly.
- **Confidence**: Seen once (start of session), most likely intentional given the "Must spend all points to continue" copy is deliberate UX, not an error — flagging only because it wasn't mentioned in the beta test plan and could surprise a tester unfamiliar with the flow.

### Finding 5 — Jambo's Tent ("Jambo Heals U") sells no healing items
- **Severity**: Low / possibly intentional (randomized stock)
- **Location**: `grondia-jambos_shop` (2,2), Jambo's buy inventory
- **Steps to reproduce**: Enter Jambo's Tent → talk to Jambo → buy
- **Expected**: Given the shop's name/flavor text ("When you blue, Jambo Heals U!"), some healing potions would be a natural fit for the buy list
- **Actual**: Stock was Silver Chain Necklace, Book, Quilted Vest, Studded Skullcap, Cloth Mitts, Gold Ring — no Restorative/Antidote for sale. (Sell tab correctly accepted my own Restoratives/Antidotes for gold, so the item types exist in the economy, just not on Jambo's buy list this session.)
- **Confidence**: Seen once; shop stock may be randomized per session/instance, so this could be a non-issue on another roll. Flagging as "possible content gap — needs verification" per the beta doc's guidance on ambiguous cases.

### Finding 6 — "World Map" has no dedicated control; it's a static label
- **Severity**: Low / non-bug
- **Location**: Movement panel header, all tiles
- **Notes**: The assignment asked to "try World Map," but "World Map" in the UI is just a section heading above the always-visible mini-map (the dot-grid overview with `©`/`●`/`◆`/`◉`/`◾` legend), not a separate clickable button or full-screen map view. The mini-map itself updates live and correctly reflects visited tiles, NPCs, items and objects throughout the session — functioning as intended, just not a discrete "feature" to click.
