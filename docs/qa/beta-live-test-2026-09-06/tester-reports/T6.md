## Findings

### F-01 — The :3000 stack ships a mangled API base URL; the game does not start at all
- **Severity:** Critical (blocks play completely, silently)
- **Location:** Global, before any gameplay
- **Steps to reproduce:**
  1. `navigate` to http://localhost:3000/games/HeartOfVirtue/
  2. `POST /games/HeartOfVirtue/api/test/session {"username":"qa_T6"}` → 201
  3. `localStorage.setItem('username','qa_T6')`, navigate again.
- **Expected:** Route to /game at GateEast.
- **Actual:** The exploration chrome renders (header, heart menu, six panel buttons) but the room panel says **`Loading location...`** forever. No error is shown to the player. Two full reloads did not help.
- **Root cause (measured in the page):**
  ```js
  (await import('/games/HeartOfVirtue/src/api/client.js')).default.defaults.baseURL
  // → "C:/Program Files/Git/games/HeartOfVirtue/api"
  ```
  and the served module text confirms it comes from the env, not the code:
  ```
  import.meta.env = {"BASE_URL":"/games/HeartOfVirtue/","DEV":true,…,
                     "VITE_API_URL":"C:/Program Files/Git/games/HeartOfVirtue/api"};
  const API_BASE_URL = import.meta.env.VITE_API_URL || '/api'
  ```
  That is MSYS/Git-Bash path conversion: the dev server was launched from a bash shell with `VITE_API_URL=/games/HeartOfVirtue/api`, and Git Bash rewrote the leading-slash value into a Windows path. `src/api/client.js` is innocent — it has no runtime override and no validation.
- **Console, repeated ~12x then silence:**
  `Error fetching explored tiles: {message: "Unsupported protocol C:", code: ERR_BAD_REQUEST}`
  `Combat status error: {message: "Unsupported protocol C:" …}`
  `Failed to fetch pending events after retries: {message: "Unsupported protocol C:" …}`
- **Two separate problems here.** (a) The launch env var is mangled — that's the harness. (b) **The client's failure mode is a permanent silent hang.** All three pollers give up after their retry budget and never resume, so even once the network came back the app stayed on `Loading location...`. A player whose API is briefly unreachable at boot gets a dead game with no message and no retry button. The one user-visible string is `Loading location...`, which is a lie.
- **Workaround used (browser-side only, no repo edit):** patch the cached axios singleton's `baseURL` and re-execute the entry module with a cache-buster so React remounts against the corrected client:
  ```js
  (await import('/games/HeartOfVirtue/src/api/client.js')).default.defaults.baseURL = '/games/HeartOfVirtue/api';
  document.getElementById('root').innerHTML = '';
  await import('/games/HeartOfVirtue/src/main.jsx?qa=1');
  ```
  This is why the console carries one `ReactDOMClient.createRoot() on a container that has already been passed to createRoot()` warning — that one is mine, not the build's. **The workaround does not survive a reload, so I never reloaded the page.**
- **Confidence:** reproduced twice (two navigations), root cause measured directly.

### F-02 — Combat verdict on a working socket: T5's F-01, F-02 and F-03 do NOT reproduce
- **Severity:** n/a (this is a clearance, recorded so the orchestrator can close them)

  - All five category buttons opened their panels on the first click. OFFENSIVE showed `Attack — Fatigue: 11 — 6 beats` with the four-segment prep/execute/recoil/cooldown bar, and greyed Attack with **`⚠ Enemy out of range (too far)`** and *range* as a glossary link.

### F-03 — After every move the Exits line and the d-pad show the *previous* tile's exits
- **Severity:** High (the player is told to walk into walls, and is not told about real exits)
- **Location:** Exploration, global; measured on eastern-descent (3,5) and nomad-camp (2,1)
- **Steps:** Move south from (3,4) to (3,5). Read the World Map footer. Do not touch anything else. Read it again after any later click.
- **Expected:** `Exits: east, north, west` (engine truth, `GET /api/world` → `{"east":{"x":4,"y":5},"north":{"x":3,"y":4},"west":{"x":2,"y":5}}`).
- **Actual:** For at least 9 s and across two screenshots the footer read **`(3, 5)` / `Exits: east, south, west`** — the coordinate had updated but the exit set had not. The ↓ button was rendered *enabled*. Clicking it did nothing; only after that dead click did the panel repaint to the correct `east, north, west`.
- **Reproduced on the camp map:** arriving at Camp (2,1) the footer read `Exits: east, northeast, south, southwest` (that is (3,0)'s set); after a dead ↙ click it repainted to `east, northeast, south, southeast`.
- This is nastier than a cosmetic lag because the *disabled state of the d-pad* is derived from the same stale set, so the affordance and the text agree with each other and both disagree with the game. T5 praised "Exits stated in text as well as by button state" (correctly) — that pairing is only a virtue when the pair is right.
- **Confidence:** reproduced on two maps, verified against the API.

### F-04 — The conversation stage never names Gorran, and dims him during his own beats
- **Severity:** High (the player cannot learn who the second figure is, and is looked away from the one thing the scene is about)
- **Location:** nomad-camp (3,0) Camp Entry, CampEntryGreetingEvent; recurs at (1,2)
- **How the stage encodes state (measured, and it is a good system):**
  - **Spoken line:** left-aligned upright monospace, orange ALL-CAPS speaker label above it, that character's portrait gets a gold frame **and a name caption underneath**.
  - **Narrated beat:** centred italic green, no speaker label, **every** portrait drops to a plain grey frame and **every caption disappears**.
  - Party on the left column, NPCs on the right. Entrances and exits are done by adding/removing the portrait (Liss appears when she runs up, is gone the beat after she bolts).
  - `alt` text is real and per-emotion: `"Jean (happy)"`, `"Gorran (neutral)"`, `"Liss (surprised)"` (`src` = `jean/happy.png`, `gorran/neutral.png`, `liss/surprised.png`). Jean visibly changed portrait 3 times in one scene, Mara twice.
- **The defect:** because the caption is bound to *is currently speaking*, and **Gorran is mute by design**, Gorran's portrait is the only one in the game that is **never captioned**. A first-time player sees an unlabelled grey armoured figure for the whole beta and is never told his name by this UI.
- **The second defect compounds it.** The scene's Gorran beats are narrated, so on exactly the lines that are *about* Gorran —
  > *"Gorran made the low sound he sometimes made — not agreement exactly, but not disagreement either. Jean had come to recognize it as a kind of knowing."*
  > *"Gorran stood beside him. Said nothing. That was usual."*
  > *"Jean watched her go, then glanced at Gorran."*

  — his portrait **dims and loses its frame** along with everyone else's. The stage directs the eye away from the subject. The character whose entire characterisation is non-verbal is the one the VN layer cannot represent.
- **Fix shape:** caption every present portrait always (dim the caption with the portrait); add a "focus" state distinct from "speaking" and give narrated beats an optional subject so Gorran's rumble lights Gorran.
- **Confidence:** reproduced across two events, DOM-measured.

### F-07 — Narrative is chunked one sentence per modal stage, with no skip and no auto-advance
- **Severity:** High (pacing — this is the game's primary delivery vehicle and it is the slowest thing in the build)
- **Location:** all story events; worst at nomad-camp (3,0)
- **Actual:** Consecutive stages of the camp-entry chain, each its own full-screen modal, each requiring a click, each typewriting at ~40 chars/s:
  - *"Jean smelled the camp before he saw it — woodsmoke, dried meat, the particular warmth of a fire that had been maintained rather than lit."*
  - *"The sound of the river was constant behind it."*
  - *"Jean stopped at the edge of the camp and let himself take it in — the fire, the packed earth, the smell of food. The river was close enough to hear."*

### F-09 — The one instruction the player must remember is dialogue only; there is no journal to put it in
- **Severity:** High (this is the beta's "what do I do next" hinge)
- **Location:** (1,2) Rivers Edge, MaraFirstContactEvent, final Mara beat
- **Actual:** The next-step instruction is delivered once, as a spoken line, in a modal that then closes:
  > `MARA` — *"Not yet, though. Raft needs restrung and I want another hour of light before I commit anyone's weight to it. Walk the camp, eat something. Come back when the sun's lower and I'll have it sorted."*

  and earlier, from Jean: *"Well — we're not getting anywhere standing here. Let's ask around, see if anyone knows a way across that river."*

- **Confidence:** quoted verbatim; panel inventory checked.

### F-10 — The NPC chat throws away the LLM's answer: the closing line is fetched, paid for, and never rendered
- **Severity:** Critical (the player pays an API call and loses the content; the conversation appears to crash)
- **Location:** (1,2) Rivers Edge, INTERACT → Mara → TALK
- **Steps to reproduce (from session start):**
  1. Reach Rivers Edge and finish MaraFirstContactEvent.
  2. INTERACT → Mara → **TALK**.
  3. Choose `[DIRECT] WHAT ELSE CAN YOU TELL ME?`
  4. Choose `[DIRECT] GO ON.`
  5. Watch the modal.
- **Expected:** Mara's reply, then either more options or a closing beat. `ai/npc/human/mara.json` even ships `closing_lines_when_exhausted` for exactly this moment (`"Mara turns back to what she was doing. The conversation is over."` and two others).
- **Actual:** The spinner ran `⟳ Mara is gathering a reply…` for ~28 s, then the **entire conversation modal vanished** and the screen fell back to Mara's INTERACT description card. No line, no closing beat, no toast, no error. It reads as a crash.
- **The server answered fine.** `POST /api/npc/chat/respond` → **200**, body:
  ```json
  {"conversation_ended": true, "llm_available": true, "turn": 4,
   "npc_response": "The crossing's passable, but the water's got teeth this time of year. Keep your feet under you and don't trust the near bank.",
   "npc_flavor": "She tilts her head toward the river, listening to something you can't hear yet.",
   "jean_options": [], "reputation": 1, "reputation_delta": 1,
   "relationship": {"attitude": "neutral", "trust_level": "Neutral"},
   "loquacity_current": 1, "loquacity_max": 15}
  ```
  That discarded line is the **only actual dialogue Mara produced in the whole conversation**, it is a good line, and it is the direct answer to the river-crossing question the beta is built around. The client is evidently keying on `conversation_ended: true` / `jean_options: []` to unmount before rendering `npc_response`.
- **Evidence:** screenshots of the spinner and of the fallback card; `read_network_requests` request id `33928.2737`.
- **Confidence:** seen once, but the network body is unambiguous and the failure is deterministic on `conversation_ended`.

### F-11 — Engine fallback stage-directions are presented as the NPC's spoken dialogue
- **Severity:** High (the player is shown a stage direction under a speaker label and cannot tell it from speech; and cannot tell a live LLM turn from a dead one)

### F-12 — The NPC chat is a 3-option picker, but nothing says so
- **Severity:** Low (T5 never reached this; the primer calls it "talk", which set my expectation wrong too)
- **Location:** Mara chat
- **Actual:** There is **no free-text input anywhere** — `document.querySelectorAll('input,textarea')` returns **`[]`** with the chat open. The player picks one of three generated lines tagged `[DIRECT]`, `[GUARDED]`, `[OPEN]`.

## Dialogue voice notes

**Scripted (non-LLM) lines — good.** Mara's scripted voice matches `mara.json`'s *"Sardonic, dry, economical. Says half of what she means… She does not explain herself."*:
> *"Crossing west?"* … *"Ten gold. Raft holds his weight fine — current's slow this time of year."* … *"It's not padded and I'm not in the mood for haggling. Take it or don't."* … *"Never had one this close. He's not going to take my raft apart, is he?"* … *"That's either agreement or he's warming up to eat something. How can you tell the difference?"*

Sparse, transactional, wry, zero warmth, zero exposition. No `prohibited_phrases` hits (`certainly`, `absolutely`, `of course`, `no worries`, `I understand how you feel`, `that must be hard`, `I'm sorry to hear that`, `feel free` — none present). ## What works well (do not regress these)

1. **The VN stage's spoken/narrated grammar.** Left-aligned + orange speaker label + gold frame + caption for speech; centred italic + no label + all portraits dim for narration. It is legible without being explained, which is the whole job. (Fix what it does to Gorran — F-04 — but keep the system.)
2. **Emotion portraits with honest `alt` text.** `jean/happy.png` → `alt="Jean (happy)"`, `liss/surprised.png` → `alt="Liss (surprised)"`. Three Jean states and two Mara states in single scenes. Screen-reader users get the emotion, not just the name.
3. **Entrances and exits are readable.** Liss's portrait appears on the right the beat she runs up and is gone the beat after she bolts; Gorran's returns when Mara notices him. No text needed.
4. **Combat on a working socket is solid.** Beat counter tracking, live move panels, the `⚠ No valid target in range` / `⚠ Enemy out of range (too far)` failure reasons with *range* linked into the glossary, the cooldown tray, the named beat-timeline chips, and the two-phase victory/loot flow with carry-weight maths.
5. **The battlefield's `⚠ Enemy off-screen — switch to Fit Fight` banner.** A pannable map that tells you when the thing you need is outside the pan, and names the control that fixes it. T5 never saw this; it's exactly right.
6. **RANDOMIZE on the level-up gate.** One click spent all 70 points and dismissed the modal. For a first-run chore the player has no information to make (T5 F-14), a working "just do something sensible" button is the correct escape hatch.
7. **The chat panel's `PREVIOUSLY` strip.** The previous line stays pinned above the current one with a mini portrait, so a two-line reply doesn't erase the question it answers.
