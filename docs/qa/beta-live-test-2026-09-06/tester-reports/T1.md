## Findings

### 1. Critical — Tile state bleeds between maps: the King Slime arena is unreachable and the player gets permanently trapped

**Severity:** Critical (route blocker + unrecoverable soft-lock, no save/load available)
**Location:** grondelith-mineral-pools (2,4) "GrondelithNarrowPass", (1,2) "GrondelithCrevice", (1,3) "GrondelithGrotto"; also reproduced on eastern-descent (2,4) "HollowClearing"

**Steps to reproduce (from session start, `full` stack):**
1. Play the briefing at Grondia (1,2), then walk south to (1,3) and south-east to Grondia **(2,4)** (this is the only route out of the start area, so every player does it).
2. Continue to the Citadel, then to Grondelith Entrance (7,9) and enter the Mineral Pools.
3. Walk (2,0) → (2,1) → (2,2) → (2,3) → **(2,4)** "Grondelith Narrow Pass".
4. Try to continue south toward (2,5)/(2,6).

**Expected:** (2,4) has exits north/east/south (map JSON `src/resources/maps/grondelith-mineral-pools.json`, key `"(2, 4)"`, `"exits": ["north","east","south"]`, `"block_exit": []`); south leads to the Approach and then the Arena where the King Slime and `Ch02ArenaEntrance` live.
**Actual:** the engine reports **only** `northwest → (1,3)`. `POST /api/world/move {"direction":"south"}` → `{"error": "Cannot go south from here", "success": false}`.

Full reachability sweep of the pools map through `/api/world/tile` (all 18 tiles):

```
(2,4) GrondelithNarrowPass ['northwest']        <- should be north/east/south
(2,5) GrondelithApproach   ['north','south']
(2,6) GrondelithArena      ['north']
REACHABLE from entry (2,0): (1,0)(1,1)(1,2)(1,3)(2,0)(2,1)(2,2)(2,3)(2,4)(3,1)(3,2)(3,3)(3,4)(4,1)(4,2)(4,3)
UNREACHABLE: (2,5), (2,6)
```

**It gets worse — the pocket closes.** After walking (2,4)→(1,3)→(1,2) the exits mutate again:

```
(1,2) GrondelithCrevice ['south']          <- was ['east','south']
(1,3) GrondelithGrotto  ['north','southeast']
(2,4) GrondelithNarrowPass ['northwest']
POST /api/world/move {"direction":"east"} -> {"error":"Cannot go east from here"}
```

Those three tiles form a closed component. Jean cannot leave the Mineral Pools at all; cloud saves 403 for test sessions, so the run is dead. That is exactly what happened to session `T1` (`T1_119_T1_trapped_pocket.png`) — I had to kill the driver and restart.

**Root cause (found by reading the source, high confidence):**
`src/api/services/game_service.py` keys tile modifications **without the map name**:

```python
# line 994  (store_tile_modification)
tile_key = f"{x},{y}"
# line 1024 (_tile_modifications)
tile_key = f"{getattr(tile, 'x', None)},{getattr(tile, 'y', None)}"
# line 1107 (apply_tile_modifications)
tile_key = f"{tile.x},{tile.y}"
```

while the neighbouring `explored_tiles` cache in the same file (line 932) *does* namespace it: `tile_key = f"{map_name}:{tile.x},{tile.y}"`. `persist_tile_state` stores `tile.block_exit` under the un-namespaced key and `apply_tile_modifications` copies it onto whatever tile in *any* map shares those coordinates.

The numbers line up exactly. `src/universe.py:344-353` turns the JSON `exits` whitelist into a `block_exit` list. Grondia (2,4) declares `["northwest","southeast"]`, so its `block_exit` is the other six directions. Applied to pools (2,4), the surviving exits are northwest (exists) and southeast (pools (3,5) doesn't exist) → `['northwest']`. Same story for (1,2): Grondia's start tile allows only `south`, so pools (1,2) collapses to `['south']`.

**Third reproduction, different map:** eastern-descent (2,4) "HollowClearing" declares `["north","east","west"]` in its JSON but the engine served `['northwest','southeast']` — Grondia (2,4)'s set again (`T1b` session, screenshot `T1b_013`).

**Evidence:** API transcripts above; `T1_119_T1_trapped_pocket.png`; `src/resources/maps/grondelith-mineral-pools.json`; `src/api/services/game_service.py` lines 932 / 994 / 1024 / 1107.
**Confidence:** reproduced in two independent sessions and on three maps; root cause read directly from source.

### 2. Critical — The combat SELECT TARGET dialog's STRIKE buttons cannot be clicked; any multi-target fight soft-locks

**Severity:** Critical (soft-lock in a mandatory encounter)
**Location:** combat UI, any encounter with more than one selectable target. Seen at grondelith-mineral-pools (2,4) (5 slimes) and eastern-descent (2,4) "Hollow Clearing" (2 Talus Hounds + Gorran as an Advance target).

**Steps to reproduce:**
1. Enter an encounter with ≥2 potential targets (or use MANEUVER → Advance, which also lists allies, so even a 1-enemy fight qualifies).
2. Pick OFFENSIVE → Attack (or MANEUVER → Advance). The "🎯 SELECT TARGET" dialog opens and renders correctly (`T1_104`, `T1b_014`).
3. Click a target's **STRIKE** button.

**Expected:** the move is committed against that target.
**Actual:** nothing happens. Playwright refuses the click with `<div>…</div> intercepts pointer events`, and a DOM hit-test confirms the button is not the element at its own centre:

```js
// both STRIKE buttons of the open dialog, eastern-descent Talus Hound fight
[ {rect:[85,460,213,44], stack:["DIV||z=auto","DIV||z=auto","DIV||z=auto","DIV||z=auto"], hasButton:false},
  {rect:[344,460,213,44], stack:["DIV||z=auto","DIV||z=auto","DIV||z=auto","DIV||z=auto"], hasButton:false} ]
```

`document.elementsFromPoint(centre)` does not contain the button at all — something transparent is stacked over the whole target list. Keyboard `1` does nothing. `CANCEL ACTION` and `✕` (lower in the dialog) *do* work, as do no-target moves (Dodge, Rest, Wait), so the player can flail but never attack or reposition.

In session 1 a programmatic `button.click()` (bypassing hit-testing) did commit the move — so the handler is wired; only the hit target is wrong. In session 2 even that stopped working and the fight froze at **BEAT 1** with the engine still waiting for Jean:
`GET /api/combat/status` → live `battle_state`, Gorran mid-`Club Strike`, Jean's slot empty. No flee/abort control is exposed anywhere in OFFENSIVE / MANEUVER / INVENTORY / MISC / DEFENSIVE, so the encounter cannot be left.

Accessibility-tree shape is suspicious and probably the lead: the dialog's buttons are reported *nested inside* the MANEUVER move panel rather than as a sibling overlay —

```
- button "Withdraw 9 beats Move away from all enemies.":
  - button "✕"
  - button "STRIKE"
  - button "STRIKE"
  - button "STRIKE"
```

**Evidence:** `T1_104_T1_advance_clicked.png`, `T1_108_T1_combat_progress.png`, `T1b_011_T1b_rumbler_done.png`, `T1b_014_T1b_combat_stall.png`; hit-test output above.
**Confidence:** reproduced in two independent sessions, three separate encounters, with exact-name locators. **Caveat worth stating:** one earlier "blocked" reading of mine was a locator artifact (`get_by_role(name="STRIKE")` substring-matches the Attack move button, whose accessible name contains "Strike at your enemy…"). The evidence above was re-gathered with `exact=True` and raw DOM hit-testing, so it is clean — but a dev should confirm with a real mouse before assuming the worst.

### 3. High — NPC `talk` result is silently discarded by the UI

**Severity:** High (UI action not working)
**Location:** grondia (10,5) "Citadel", Grondite Elder (both instances). Applies to any non-LLM NPC (`llm_chat_enabled: false`).

**Steps to reproduce:**
1. Reach the Citadel (10,5).
2. INTERACT → "Grondite Elder" → **TALK**.

**Expected:** the elder's line is displayed.
**Actual:** nothing renders — no dialog, no log line, no error. Waited 30 s across three attempts.

The request *is* sent and *does* succeed; the frontend just drops the payload:

```
REQUEST  POST /api/world/interact {"target_id":"57c21bea…","action":"talk","quantity":null}
STATUS   200
BODY     {"action":"talk", …, "message":"The Elder turns. He looks at Jean the way a geologist looks at a
          particular stratum — with genuine, slow interest. Then he makes a single sound, deep and
          resonant, and returns his gaze to the middle distance.", "success":true,
          "events_triggered":[{"name":"AfterKingSlimeReturn","needs_input":false,"description":"", …}]}
```

Note `events_triggered` carries a non-completed event with an empty description on *every* talk; a plausible suspect is the interaction handler branching into event display and swallowing `message`. READ on an object in the same panel works fine, so the panel is not globally locked.

**Evidence:** `T1_090_T1_elder_talk.png`, `T1_092_T1_talk_noop_retry.png`, request/response capture above.
**Confidence:** reproduced three times in session 1.

### 7. Low — Autosave 403 spam

## Non-bug observations

- **O1 — combat difficulty.** Across two full encounters (5 slimes + stone creature; 1 rock rumbler) Jean took **zero** damage; HP stayed at 100/158 and 100/136 throughout. Slimes die in one hit (72 damage from the Shortsword of Insight +3). The pre-seeded level-10 loadout makes the beta's ordinary encounters a formality — worth checking that the King Slime is actually tuned against this loadout.
- **O2 — `AfterKingSlimeReturn` reported as "triggered" when it isn't.** Every `world/interact` at the Citadel returns it in `events_triggered` with `completed:false`, `needs_input:false` and an empty description. Gating is correct (nothing fires), but anything downstream that trusts `events_triggered` will be misled.
- **O3 — stale tactical advisor.** At the start of the Talus Hound fight the advisor's "ANALYSIS OF PREVIOUS CYCLE" quoted the *previous* encounter's Rock Rumbler lines.
- **O4 — item grant ordering.** In the Votha Krr scene the mechanical grants ("Jean adds Antidote (x5)…") appear *before* the narration that explains the attendant handing over the bundle, and are then repeated as "[Received: 5 Antidotes, 2 Restoratives]". Three renderings of one event.
- **O5 — target dialog wording.** The confirm button in SELECT TARGET is labelled **STRIKE** even when the move is Advance or Withdraw, and the list includes allies (Gorran) — "STRIKE Gorran (4 ft)" reads badly.
- **O6 — party display.** Gorran is listed in `where().npcs` on Grondia and the eastern descent but vanished from the tile roster in the Mineral Pools while still being narratively present.
- **O7 — writing quality.** The Votha Krr scene is genuinely good: "unhurried as erosion", "the way a canyon regards a river", "He said it the same way he'd said it the first time. Like a door left open." No truncation, no placeholder text, speaker attributions correct throughout, portraits swapped correctly (Jean/Gorran → Jean/Elder → Jean/Votha Krr).
