# Testing rules

## Running
- `python -m pytest -q` — never bare `pytest`. All of `pytest.ini` is three settings: `norecursedirs` (`tests/broken`, `tests/uat`, `tests/integration`, `.claude` — `tests/api` used to be listed here and is not any more; it runs in the gate), `testpaths = tests`, and `addopts = -n auto --dist loadfile`. There are no `--ignore-glob` entries; the seven that used to sit there named `debug_*`/`check_*`/`find_*`/`reproduce_*`/`verify_*`/`uat_*`/`manual_*`, none of which pytest's default `python_files` (`test_*.py`, `*_test.py`) ever matched, so they guarded nothing and were deleted. CI (`ci.yml`) runs `python -m pytest -q -n auto` and `flake8 --extend-ignore=E501 src/`; `test-coverage.yml` enforces backend ≥85% / frontend ≥95%.
- Review-rule unit tests run separately: `python -m pytest .claude/skills/_shared/review_rules/test_code_review_rules.py -v` (and `test_code_scrubber_rules.py`).
- Live-provider tests: `HOV_LIVE_LLM=1 python -m pytest tests/integration/ -q` (excluded from the default run). **Do not gate them on `MYNX_LLM_ENABLED`/`MYNX_LLM_PROVIDER`** — `tests/conftest.py` pins those to `0`/`none` suite-wide, so such a module skips itself unconditionally (which is how `test_tactical_advisor_live.py` stayed inert for its whole existence). `tests/integration/conftest.py`'s `live_env` restores the real `.env` provider for one module and puts the pins back, including clearing `NpcChatLLMAdapter._instances` (which `reset_class_state()` does not touch and production populates via `get_instance`/`prewarm`). See `.claude/rules/llm-prompts.md` before editing a prompt.
- No pre-commit hook is installed (worktrees share `../.git/hooks`, which holds only samples). Optional local hook: a `pre-commit` script that runs `python -m pytest -q --tb=line || exit 1`.

## Where tests go
- **Full-app integration tests that build a real session/universe** (`create_app(TestingConfig)` + `/api/test/session`) go in `tests/api/`, which is **not** excluded from the default run. Creating a real session mutates module-level item/merchant registries, so such a module depends on its own internal ordering; `--dist loadfile` schedules a whole file onto one worker, which is what keeps that ordering intact. Other route tests use a *mocked* `session_manager`. Pure in-memory engine fuzz (serializer, save) lives under `tests/`.
- `tests/acceptance/<slug>/` — generated by `python tools/acceptance_test_generator.py --feature "…" --output tests/acceptance/<slug>` (config.ini, run.sh, test_plan.json, a 2-tile map, a harness scenario, README). Register the scenario in `tools/harness/scenarios/__init__.py` to make it part of `bug_hunt.py`.

## Pollution and isolation gotchas
- A stray root-level script that does `sys.modules['flask'] = MagicMock()` at import would poison every Flask test in a full run. `testpaths = tests` closes this structurally — pytest no longer walks the repo root at all, so a rootdir `test_*_fix.py` is simply never collected, and nothing needs adding to `pytest.ini` per script. (It is also why collection is ~3.3s instead of ~6.2s, paid per xdist worker.) A script under `tests/` is still collected: to find a collection-time culprit there, hook `pytest_collection_finish` and check `type(sys.modules['flask'])`.
- **There is no bare-name import aliasing any more.** `src/import_sync.py` and the old `tests/conftest.py` hooks that mapped bare engine names onto `src.` modules are retired; `tests/conftest.py` puts only the project root on `sys.path`, and `tests/api/conftest.py` installs no module shims. Nothing collapses a bare/`src.` module split at runtime, so the guard is static: `tests/test_no_bare_local_imports.py` AST-parses `src/` and `tests/` and fails on any bare local import. If you hit a duplicate-module `isinstance` failure, the fix is the import statement, not a shim.
- Stubbing a module imported as `import src.x as m`: patching `sys.modules["src.x"]` is not enough — that import binds through `getattr(src, "x")`, so patch the `src` package attribute too (`_fake_engine_modules` in `tests/test_session_manager_coverage.py`). To pass an engine `isinstance`, set `mock.__class__` to the real class or build with `RealClass.__new__(RealClass)`.
- `patch_terminal_output` (autouse) mocks `cprint`/`print_slow`/etc. — story events print Unicode box-drawing that raises `UnicodeEncodeError` on a cp1252 Windows console. Don't remove it; don't print from tests.
- Randomness: the engine makes ~220 unseeded `random.*` calls (only `positions.py` seeds). Seed (`random.seed(n)`) or `monkeypatch` the roll; never assert on an unseeded outcome.
- `config_combat_testing.ini` is a mutable surface other agents/skills edit — don't assert on its exact values; create a scratch config (xdist-worker-unique filename) instead.
- `test_session_manager_coverage.py::test_apply_player_stats_relative_path` is a known cwd-dependent flake under `-n auto` — it passes in isolation. Confirm with a targeted run before investigating; it is not caused by whatever you just changed.
- Session state: direct `game_service` calls mutate `session.data` in memory; call `session_manager.save_session()` before issuing API requests that must see it. `process_event_input` mints a new `event_id` per stage — always use the id from the latest response.
- `.env` leaks into pytest through `src/env_bootstrap.load_project_env()`, which `src/api/db.py`, `src/api/rate_limiter.py` and `ai/llm_client.py` each call at their own import time — importing any one of them is enough. `tests/conftest.py` therefore blanks the credentials and `LOG_LEVEL` before those imports. It iterates `tests/llm_doubles.CREDENTIAL_ENVS`, which is `PROVIDER_KEY_ENVS` (derived from `ai.llm_client._OPENAI_COMPATIBLE_PROVIDERS`, not transcribed) **plus `GITHUB_TOKEN`** — so the suite *does* blank `GITHUB_TOKEN`, and a test reaching the feedback route needs no blanking of its own. Leave it in `CREDENTIAL_ENVS`: `feedback.py`'s issue filing has no TESTING guard by design, and an unblanked token is how a harness run once filed 20 real GitHub issues. The conftest also blanks `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`, one layer down from the same hazard: `src/api/db.py` reads the URL straight from the environment rather than from Flask config, and `auth_service.create_user` has no TESTING guard, so a walked test that reaches `POST /api/auth/register` would write a real row to the live database. Blanked, it fails loudly with "TURSO_DATABASE_URL is not set" instead of succeeding against production. Assign `""`, never `.pop()` — `load_dotenv(override=False)` refills a key that is *absent* and leaves an assigned blank one alone.

## Harness (`tools/bug_hunt.py`, `tools/harness/`)
Scenarios extend `Scenario` (ABC) in `tools/harness/scenarios/` and implement `run(client) -> List[BugReport]`; 22 exist (health, auth, world, combat, inventory, player, saves, phase3, no_auth, combat_edge, inventory_actions, ch01/ch02/ch03 events, ch01_wrong_choice, grondia_happy_path, ally_progression, shop, npc_chat, logs, feedback, debug_ops). Helpers: `_check_status(resp, expected)`, `_check_no_crash(resp)` (5xx only — use for bad-input probes), `_check_rejected`, `_check_fields(data, fields)`, `_bug(...)`. `--headless --output bugs.json` for CI (`.github/workflows/bug-hunt.yml`); fix-agent prompt at `tools/harness/prompts/bug_hunt_prompt.txt`. The harness blanks `GITHUB_TOKEN` before `create_app` so the feedback scenario doesn't file real issues — keep that.

## Browser QA
`python tools/inquisitor.py [--headless --output …] [--no-browser]` — deterministic probe sequence through the real React + Flask stack (Playwright Chromium: `pip install playwright asgiref && python -m playwright install chromium`). Setup, auth bypass (`FLASK_ENV=testing` + `/api/test/session`), known noise, and screenshot paths: `docs/qa/inquisitor.md`. `/qa` (gstack) is the interactive alternative. Before filing UI "bugs", read the QA section in root CLAUDE.md — many are puzzles.

## Contract tests (keep them green, extend them)
`test_wire_field_contract.py` (client-read fields ⊆ real serializer output), `test_move_categories_ui_contract.py` (every castable category reaches a button group), `test_move_web_animations.py` (`web_animation` keys valid), `test_no_bare_local_imports.py` + `test_import_sync_production.py` (canonical `src.` imports, `LEGACY_BARE_MODULES`), `test_player_stat_derivations.py`, `test_serializer_fuzz.py`, `test_save_fuzz.py`. When you add a client read, a move, a module, or a serializer, the matching contract test changes in the same commit.
