# Testing rules

## Running
- `python -m pytest -q` — never bare `pytest`. `pytest.ini` excludes `tests/api`, `tests/broken`, `tests/uat`, `tests/integration`, `.claude`, plus ignore-globs for root-level `debug_*/check_*/find_*/reproduce_*/verify_*/uat_*/manual_*.py` and a few named tier-4 files. CI (`ci.yml`) runs `python -m pytest -q -n auto` and `flake8 --extend-ignore=E501 src/`; `test-coverage.yml` enforces backend ≥85% / frontend ≥95%.
- Review-rule unit tests run separately: `python -m pytest .claude/skills/_shared/review_rules/test_code_review_rules.py -v` (and `test_code_scrubber_rules.py`).
- No pre-commit hook is installed (worktrees share `../.git/hooks`, which holds only samples). Optional local hook: a `pre-commit` script that runs `python -m pytest -q --tb=line || exit 1`.

## Where tests go
- **Full-app integration tests that build a real session/universe** (`create_app(TestingConfig)` + `/api/test/session`) go in `tests/api/` — creating a real session mutates module-level item/merchant registries and pollutes downstream shop/spawn tests. Other route tests use a *mocked* `session_manager`. Pure in-memory engine fuzz (serializer, save) lives under `tests/`.
- `tests/acceptance/<slug>/` — generated by `python tools/acceptance_test_generator.py --feature "…" --output tests/acceptance/<slug>` (config.ini, run.sh, test_plan.json, a 2-tile map, a harness scenario, README). Register the scenario in `tools/harness/scenarios/__init__.py` to make it part of `bug_hunt.py`.

## Pollution and isolation gotchas
- Stray root-level scripts that do `sys.modules['flask'] = MagicMock()` at import poison every Flask test in a full run (pytest collects them from rootdir). `pytest.ini`'s ignore-globs neutralize the known ones; add new ones there. To find a collection-time culprit, hook `pytest_collection_finish` and check `type(sys.modules['flask'])`.
- The `_synchronized_import` hook in `tests/conftest.py` aliases bare engine names to `src.` modules; `_NO_BARE_ALIAS = {'api'}` keeps the bare `api` name from being aliased onto `tests/api/` (which broke collection and `create_app()`). API sub-packages are pre-loaded in `tests/api/conftest.py`.
- Stubbing a module imported as `import src.x as m`: patching `sys.modules["src.x"]` is not enough — that import binds through `getattr(src, "x")`, so patch the `src` package attribute too (`_fake_engine_modules` in `tests/test_session_manager_coverage.py`). To pass an engine `isinstance`, set `mock.__class__` to the real class or build with `RealClass.__new__(RealClass)`.
- `patch_terminal_output` (autouse) mocks `cprint`/`print_slow`/etc. — story events print Unicode box-drawing that raises `UnicodeEncodeError` on a cp1252 Windows console. Don't remove it; don't print from tests.
- Randomness: the engine makes ~220 unseeded `random.*` calls (only `positions.py` seeds). Seed (`random.seed(n)`) or `monkeypatch` the roll; never assert on an unseeded outcome.
- `config_combat_testing.ini` is a mutable surface other agents/skills edit — don't assert on its exact values; create a scratch config (xdist-worker-unique filename) instead.
- Session state: direct `game_service` calls mutate `session.data` in memory; call `session_manager.save_session()` before issuing API requests that must see it. `process_event_input` mints a new `event_id` per stage — always use the id from the latest response.
- `.env` leaks into pytest via `src/api/db.py`'s `load_dotenv()` at `create_app()` import. Neutralize live secrets explicitly (`os.environ["GITHUB_TOKEN"] = ""`, not `.pop()` — `override=False` refills missing keys).

## Harness (`tools/bug_hunt.py`, `tools/harness/`)
Scenarios extend `Scenario` (ABC) in `tools/harness/scenarios/` and implement `run(client) -> List[BugReport]`; 22 exist (health, auth, world, combat, inventory, player, saves, phase3, no_auth, combat_edge, inventory_actions, ch01/ch02/ch03 events, ch01_wrong_choice, grondia_happy_path, ally_progression, shop, npc_chat, logs, feedback, debug_ops). Helpers: `_check_status(resp, expected)`, `_check_no_crash(resp)` (5xx only — use for bad-input probes), `_check_rejected`, `_check_fields(data, fields)`, `_bug(...)`. `--headless --output bugs.json` for CI (`.github/workflows/bug-hunt.yml`); fix-agent prompt at `tools/harness/prompts/bug_hunt_prompt.txt`. The harness blanks `GITHUB_TOKEN` before `create_app` so the feedback scenario doesn't file real issues — keep that.

## Browser QA
`python tools/inquisitor.py [--headless --output …] [--no-browser]` — deterministic probe sequence through the real React + Flask stack (Playwright Chromium: `pip install playwright asgiref && python -m playwright install chromium`). Setup, auth bypass (`FLASK_ENV=testing` + `/api/test/session`), known noise, and screenshot paths: `docs/qa/inquisitor.md`. `/qa` (gstack) is the interactive alternative. Before filing UI "bugs", read the QA section in root CLAUDE.md — many are puzzles.

## Contract tests (keep them green, extend them)
`test_wire_field_contract.py` (client-read fields ⊆ real serializer output), `test_move_categories_ui_contract.py` (every castable category reaches a button group), `test_move_web_animations.py` (`web_animation` keys valid), `test_no_bare_local_imports.py` + `test_import_sync_production.py` (canonical `src.` imports, `LEGACY_BARE_MODULES`), `test_player_stat_derivations.py`, `test_serializer_fuzz.py`, `test_save_fuzz.py`. When you add a client read, a move, a module, or a serializer, the matching contract test changes in the same commit.
